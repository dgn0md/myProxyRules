# 模块化与动态规则集开发原则

与 [AGENTS.md](../AGENTS.md) 和 [国内 DNS 白名单原则](dns-whitelist.md) 一同执行，约束模块划分、上游选源、精确例外与验收方式。

## 1. 模块组织与开关设计

| 原则 | 执行标准 |
| --- | --- |
| **按用途组织模块** | 按服务类别、厂商或明确路由用途组织声明式 provider、出口与优先级；不为单个业务域名或测试端点新建模块/分支。 |
| **复用统一开关** | 13 组国内厂商模块与 `DOMAIN-SUFFIX,cn,直连` 统一由 `国内服务优先直连` 控制，不设单厂商开关。 |
| **路由与 DNS 解耦** | 统一国内服务路由开关不替代默认启用的 `dns_domestic_cdn`、`dns_microsoft_cdn` 边界；连接出口与 DNS 解析器分别验证。 |
| **零冗余接口** | 删除废弃功能时同步移除无用导出、包装层、文件与文档引用；内部复用以实际职责为依据，不为未来假设预留接口。 |

## 2. 上游选源与更新机制

| 步骤 / 环节 | 要求 |
| --- | --- |
| **1. 排查漏匹配** | 先确认实际请求域名、当前规则版本与命中规则，再核查 Bett Rules、Sukka、Blackmatrix7 等现用上游分类。 |
| **2. 审查实际成员** | 必须检查成员覆盖、海外业务、共享 CDN、广告与专用服务重叠；不得仅凭规则名或厂商归属决定直连或国内 DNS。 |
| **3. 集合关系表达** | 需排除海外业务时，在内核中以 `AND NOT` 表达（如 `domestic AND NOT domestic_noncn`）；不无条件直连整家厂商、公共云或整个 `cn` 集合。 |
| **4. 客户端直连更新** | 客户端通过 HTTP provider 每 `86400s` 拉取上游；仓库不筛选、合并或重发布成员清单。CI 与构建工具只负责从唯一脚本生成配置、摘要与 CDN 副本。 |
| **5. 测试快照隔离** | 原生校验下载/解码的快照仅存于忽略目录，严禁进入客户端配置或发布产物。 |

> 海外 `@!cn` 子集仅代表上游已标注成员，排除后不保证剩余域名全部位于大陆；专用服务规则始终保持更高优先级。

## 3. 精确例外准入标准

动态集合优先，不默认逐域名打补丁。现有 Apple / 协议等有明确功能依据的精确例外按各自约定维护；新增精确例外须同时满足：

1. **集合无法表达**：说明现有上游动态集合为何无法准确覆盖或边界过宽。
2. **明确范围与优先级**：记录精确主机/后缀/正则边界及其与前置/后置规则的先后关系。
3. **配套回归断言**：在配置测试与原生回环测试中覆盖正例与排除边界。
4. **禁止测试页驱动**：不得仅为让某个测速/检测页显示预期出口而添加业务域名规则。

## 4. 路由与 DNS 验收边界

| 验收维度 | 必须覆盖的内容 |
| --- | --- |
| **规则顺序** | 专用服务与 Apple 精确例外 → 广告/HTTPDNS → 前置直连与服务组 → `dns_domestic_cdn` → 13 组国内厂商（`AND NOT @!cn`）→ `geolocation-cn` → `.cn` → `category-stun` → `geolocation-!cn` → IP 兜底。 |
| **DNS 一致性** | 显式直连域名/集合使用同谓词国内 DoH；代理服务组跟随对应组出口；`geolocation-cn` 独立生效；关闭 `国内服务优先直连` 后同步清理厂商与 `+.cn` 的路由及 DNS policy，并保留仍被引用的 provider。 |
| **原生抽样** | 从实际公开快照自动提取命中与排除样本，集合外使用合成 `.invalid` 域名，不维护独立业务域名清单。 |
| **门禁范围** | 行为变更覆盖全量/极简、静态/展开与开关组合；只改文档时核对链接与原则一致性，不声称已完成网络实测。 |
